# Intern 重设计

> 状态：**设计稿**，2026-11-15（当日按**桌面应用**改版，原纯命令行方案作废）。
> 技术栈已定：**Go + Wails v2 + React/TypeScript**（第 6.4 节）。
> **配色不在本文范围内**，后面单独调。

---

## 0 一句话

Intern 是赛事的官方 AI 编程工具。这次重做成**桌面应用**（Wails + Web 前端），
交互参照 Codex / Claude Code 的对话式体验，代码**完全自研**——不引用 opencode，
也不引用原仓库 `apps/intern` 的任何一行。

---

## 1 为什么重写

三个理由，缺一个都可以选择沿用旧代码：

| 理由 | 事实 |
| --- | --- |
| **许可证** | opencode 是 MIT，可以合法 fork 但要保留第三方版权声明；`JaaamesZhang/Unscripted` 根目录**没有 LICENSE**，默认保留所有权利，James 写的定制层不能拷 |
| **形态** | 现在是 Electron 壳里套 Vue 界面 + 内嵌终端，自有代码 152 MB、主 chunk 单文件 39 MB，启动和体积都重。桌面应用直接复用系统 WebView，不需要这一整套 |
| **痕迹** | 目标仓库里每一行都可追溯到本人。以 fork 起步的仓库做不到这一点，无论怎么改名 |

**不重写的部分**：赛事平台本身、后端契约、作品数据。Intern 是客户端，接口早就定好了。

## 2 现状（可核实的部分）

### 2.1 分发

| 项 | 值 |
| --- | --- |
| Windows | `Intern-0.4.12-win-x64.exe`（145 MB）+ 同版本 zip（197 MB） |
| macOS | `Intern-0.3.0-mac-arm64.dmg`（174 MB） |
| 更新 | `latest.yml` / `latest.json`，electron-updater 格式，含 sha512 与体积 |
| 发布 | `releaseDate: 2026-10-18`（Windows 0.4.12） |

macOS 侧版本落后 Windows 两个 minor，说明双平台是分别维护的——重写时应当用同一份源码出两个平台的包，消除这个漂移。

### 2.2 技术形态

拆开 `app.asar` 看到 8,099 个文件，其中自有代码 2,143 个文件 / 152 MB：

- **壳**：Electron（`Intern.exe` + Chromium 运行时 + 77 个 locale）
- **界面**：Vue 渲染层（`out/renderer/`），终端用 `ghostty-web` 内嵌
- **解析**：tree-sitter（bash、powershell 等）做语法分析，shiki 做高亮，按语言拆成独立 chunk
- **底座**：`anomalyco/opencode` 的 fork，代码里仍保留指向 opencode 的文档与 issue 链接

结论：它本质是一个**带图形界面的终端**，不是命令行工具。这次要的是反过来——一个真正的 CLI。

### 2.3 平台对接

从主进程代码里读到的配置：

```
gatewayUrl   https://platform.scie1024.dev
oauthUrl     https://scie1024.dev/api/oauth
oauthClientId  intern...（截断）
callback      http://127.0.0.1:<port>/oauth/callback    （loopback，标准原生应用流程）
```

旧版用 `platform.scie1024.dev` 作网关，新后端的网关挂在同一个域名的 `/v1` 下，重写时要改成新地址。

### 2.4 后端已经准备好的能力

契约里已有、正是为客户端准备的端点（`docs/api/openapi.json`）：

| 用途 | 端点 |
| --- | --- |
| 授权服务器元数据 | `GET /.well-known/oauth-authorization-server`（RFC 8414） |
| 授权码 + PKCE | `GET /api/v1/oauth/authorize`、`/consent`、`POST /token`、`POST /revoke`、`GET /userinfo` |
| 推理 | `POST /v1/chat/completions`（OpenAI 兼容，转发上游并计费） |
| 模型列表 | `GET /v1/models` |
| 我的用量 | `GET /api/v1/usage/summary`、`/usage/requests`、`/usage/team` |
| 设备管理 | `GET /api/v1/me/connected-apps`、`DELETE .../{client_id}/devices/{device_id}` |
| 账号 | `GET/PATCH /api/v1/me`、`/me/api-keys` |

`docs/api/conventions.md` 已经写明桌面端的鉴权方式：

> 桌面端 `Authorization: Bearer <oauth access token>`，授权码 + PKCE，走 `/oauth/*`

也就是说**平台侧不需要为 Intern 重做任何接口**。这是"弱绑定"能成立的前提。

## 3 定位与边界

### 3.1 是什么

一个装在终端里的 AI 编程助手。打开项目目录，敲 `intern`，用自然语言让它读代码、改代码、跑命令。

### 3.2 谁用

| 角色 | 典型用法 |
| --- | --- |
| 参赛者 | 主场景：写自己的作品代码 |
| 队长 | 同上，另加查看队伍额度 |
| 评委 / 主办 | 只读审阅，或本身也用它写东西 |
| 围观者 | 大概率不用 |

### 3.3 弱绑定规则

这是本次最重要的产品决策：**登录是可选增强，不是使用前提**。

| 状态 | 能做什么 | 走哪个通道 |
| --- | --- | --- |
| 未登录 | 用自己填的 API key 走任意 OpenAI 兼容服务 | 用户配置的 `base_url` |
| 已登录 | 用平台额度，模型由主办方配置，用量计入队伍 | `platform` 网关 |
| 已登录 + 自带 key | 两者都在，运行时切换 | `intern model` 或 `/model` |

三条硬要求：

1. **未登录时不能有任何功能降级提示反复骚扰**。只在用户主动敲 `/login` 或模型不可用时提示一次。
2. **登录不能阻塞启动**。网络不通、平台 5xx、额度耗尽，都必须还能用自带 key 继续干活。
3. **凭据永不落明文**。见第 10.3 节。

### 3.4 明确不做

写下来是为了防止范围膨胀：

- 不做终端版（形态已定为桌面应用；CLI 以后再说，但内核按可复用写）
- 不做网页版 / 云端 IDE
- 不做代码托管、不做 CI
- 不做团队实时协作（多人在同一会话里）
- 不做插件市场（MCP 是配置项，不是商店）

## 4 交互模型

形态是桌面应用，不是终端。主界面固定三栏：

```
┌─────────────┬────────────────────────────────┬──────────────┐
│ 会话         │  把登录页换成深色主题            │ 相关文件      │
│             │                                │ ▾ src/       │
│ ● 登录页     │  你：把登录页换成深色主题         │   ▾ pages/   │
│ ● 修 bug     │  Intern：先看一下现在的实现…      │     login.tsx│
│ ● 投票页     │                                │   ▸ components│
│             │  ● Read  src/pages/login.tsx   │ ▸ public/    │
│             │                                │              │
│             │  ╭─ 改动审阅（悬浮）──────────╮  │              │
│             │  │ login.tsx   +12 −4         │  │              │
│             │  │ [接受] [回退]               │  │              │
│             │  ╰────────────────────────────╯  │              │
│             │  ┌────────────────────────────┐ │              │
│             │  │ > 继续输入…                 │ │              │
│             │  └────────────────────────────┘ │              │
│ (头像) 用户名│                                │              │
└─────────────┴────────────────────────────────┴──────────────┘
```

### 4.1 三栏的职责

| 栏 | 内容 | 说明 |
| --- | --- | --- |
| 左 | 会话列表 | 时间倒序；用户头像、名字与登录状态压在**左下角** |
| 中 | 对话 | 消息流 + 输入框；**改动审阅悬浮在输入框正上方** |
| 右 | 相关文件 | 本次会话引用过的文件，按**文件夹树**展开 |

改动审阅做成悬浮层而不是独立一栏：它只在有改动时出现，固定占一栏会让平时多出一块空白。

### 4.2 三条交互原则

1. **默认安静**。能一句话说清的不用三行；工具调用折叠成一行，展开才看细节。
2. **随时可中断**。`Esc` 立刻停下当前推理或工具调用，保留已有上下文。
3. **破坏性操作先问**。删文件、`git push --force`、`rm -rf`、写项目外的路径——一律确认。

### 4.3 运行形态

只有 GUI。批处理与脚本化的能力以后通过 CLI 提供，内核按可复用写（见 6.1）。

### 4.4 快捷键与命令

| 操作 | 快捷键 |
| --- | --- |
| 发送 | `Enter`（输入法选词时不触发） |
| 换行 | `Shift + Enter` |
| 中断当前响应 | `Esc` |
| 新会话 | `Ctrl + N` |
| 搜索会话 | `Ctrl + K` |

斜杠命令在输入框里输入 `/` 触发，自己实现、不走模型，响应必须即时：

| 命令 | 作用 |
| --- | --- |
| `/login` `/logout` | 平台账号 |
| `/whoami` | 当前身份、队伍、额度余量 |
| `/model` | 切换模型 / 通道（平台 / 自带 key） |
| `/usage` | 本次会话与本月用量 |
| `/clear` | 清空当前会话上下文 |
| `/compact` | 压缩上下文，保留摘要 |
| `/init` | 扫描项目生成 `INTERN.md` |
| `/config` | 打开配置文件 |
| `/doctor` | 自检：网络、凭据、git 状态、上游可用性 |

### 4.5 权限确认

三种策略，默认「问」：

| 策略 | 触发条件 | 行为 |
| --- | --- | --- |
| 只读（默认允许） | 读文件、搜代码、列目录 | 不问 |
| 写入项目内（默认问） | 改文件、跑命令 | 问一次，可「本会话内同类都允许」 |
| 项目外 / 破坏性（永远问） | 写 `~` 或系统目录、`rm -rf`、强制推 | 每次都问，不给「永久允许」 |

规则可以被项目配置覆盖（`INTERN.md` 或 `.intern/settings.json`），但**永远问**那一档不可覆盖。
完整的判定顺序、以及「本会话都允许」的作用边界见 15.1。

### 4.6 会话恢复

- 启动默认打开上一次的会话
- 左栏点任意会话切换，无需命令
- 会话按项目根目录隔离，跨项目不串味（见 15.11）

## 6 架构

### 6.1 进程模型

Wails 的模型是「Go 主进程 + 系统 WebView」：

```
intern.exe / intern.app
├── Go 内核（主进程）
│   ├── 会话状态、配置、凭据
│   ├── LLM 请求（流式）
│   └── 工具执行（子进程：shell / rg / git）
└── WebView2 / WKWebView（渲染进程）
    └── React 界面，通过 Wails 绑定调用 Go 方法
```

Go 侧只暴露少量方法（`GetBootstrap`、`SendMessage`、`AcceptDiff` 等），
界面状态留在前端。**不自己设计 IPC 协议**——这是选 Wails 而不是 Tauri 的主要理由。

Windows 上 WebView2 由系统提供（装了 Edge 就有），不打包 Chromium。

### 6.2 模块

```
main.go              Wails 入口，窗口参数
app.go               绑定给前端的方法
internal/agent/      主循环：消息 → 模型 → 工具 → 结果
internal/provider/   统一模型接口 + 平台网关 / 自带 key
internal/tools/      工具注册表 + 每个工具一个文件
internal/edit/       精确替换、patch 应用、原子写、diff 生成
internal/session/    会话存储、恢复、压缩
internal/auth/       OAuth PKCE、令牌刷新、系统钥匙串
internal/config/     分层配置合并、校验（已实现）
internal/perm/       权限策略判定
internal/platform/   平台 API 客户端（登录、用量、设备）
internal/project/    项目根与分支识别（已实现）
internal/media/      图片派生管线（网站侧共用）
frontend/            React + TypeScript + Vite
```

依赖方向：`frontend → app.go → internal/*`。`tools` 不引用窗口，`provider` 不引用 `session`，
这样以后加 CLI 前端时内核可以直接复用。

### 6.3 一次请求的数据流

```
按键 → tui 收集输入
     → agent 组装上下文（系统提示 + INTERN.md + 会话历史 + 当前输入）
     → provider 发起流式请求
     → 边收边渲染（tui 只负责画，不解析语义）
     → 模型要调工具 → perm 判定 → tools 执行
     → 结果回填历史 → 再请求
     → 直到模型不再调工具 → 落盘会话
```

关键点：**渲染层不解析业务语义**。agent 吐出结构化事件（`TextDelta`、`ToolStart`、`ToolResult`、`Done`），tui 只消费事件。这样换渲染方式不影响逻辑。

### 6.4 技术选型（已定：Go + Wails v2 + React/TypeScript）

最初选过 Go + bubbletea 的纯终端方案，改为桌面应用后重选。三个候选的对比留作决策记录：

| 维度 | **Go + Wails（选定）** | Tauri（Rust 壳） | Electron |
| --- | --- | --- | --- |
| 体积 | 约 12 MB（实测） | 约 6 MB | 约 150 MB |
| 内存 | 100–150 MB（含 WebView 进程） | 90–140 MB | 200–300 MB |
| 前后端通信 | Wails 自动生成绑定 | 自己定 IPC 协议 | 自己定 IPC 协议 |
| Go 内核复用 | 直接复用，同进程 | 需另起子进程 | 需另起子进程 |
| 界面能力 | Web 全部能力 | Web 全部能力 | Web 全部能力 |
| 分发依赖 | 系统 WebView（Win10/11 自带） | 同左 | 自带 Chromium |

**已定 Go + Wails**，核心是三条：Go 内核与界面同进程、绑定自动生成、体积只有 Electron 的十二分之一。

代价是要维护一套前端工程。这是值得的：三栏布局、悬浮审阅、代码高亮、diff 视图在 Web 生态里
都是现成组件；纯 Go 原生 GUI（Fyne / Gio）要全部自己画，而且中文输入法一直是弱项。

**不能交叉编译**：Windows 的包在 Windows 上出，macOS 的包在 macOS 上出。
这点和纯命令行方案不同，排期要按两个平台的构建环境算。

## 7 与平台的接口（弱绑定）

### 7.1 登录：OAuth 授权码 + PKCE

标准原生应用流程，不引入回调域名：

```
1. intern login
   ├─ 生成 code_verifier（43–128 字符随机串）与 code_challenge = S256(verifier)
   ├─ 起一个本地 HTTP 监听：http://127.0.0.1:<临时端口>/oauth/callback
   ├─ 打开浏览器到 /api/v1/oauth/authorize?response_type=code&client_id=...&
   │     redirect_uri=http://127.0.0.1:<port>/oauth/callback&
   │     code_challenge=...&code_challenge_method=S256&scope=profile+llm
   ├─ 用户在浏览器里确认（/consent）
   └─ 浏览器跳回 loopback，拿到 code
2. POST /api/v1/oauth/token  grant_type=authorization_code + code_verifier
   → access_token / refresh_token / expires_in
3. 存 refresh_token 到系统钥匙串，access_token 存内存
4. 到期前 60 秒用 refresh_token 换新（轮换：旧 refresh_token 立即失效）
```

要点：

- **不写死端口**，让系统分配——固定端口会和用户本地服务打架
- loopback 监听只活到拿到 code，拿到即关
- `state` 参数必须校验，防 CSRF
- 授权服务器元数据从 `/.well-known/oauth-authorization-server` 拉取，不硬编码端点地址（换域名不用改客户端）
- `intern logout` 调 `POST /api/v1/oauth/revoke` 后才删本地令牌
- **`client_id` 沿用旧版的 `intern`，不重新注册**。旧平台已有的 `connected-apps` 记录与用户授权都指向它，
  用户数据已经迁过来了，换 id 等于让所有人重登一次，没有理由付这个代价
- **没有浏览器的环境**（SSH 到服务器、无 GUI 的 macOS）不能直接判定失败：打印授权 URL 让用户在自己的机器上打开，
  再让用户把回调地址或 code 粘回来。细节见 15.2

### 7.2 推理：`/v1/chat/completions`

OpenAI 兼容，所以：

- 请求体按 OpenAI 格式，`stream: true` 拿 SSE
- 响应里出现未知字段一律忽略（契约里 schema 是 `additionalProperties: true`，形状没固化）
- 模型列表从 `GET /v1/models` 拉，缓存 5 分钟
- **不硬编码模型名**。主办方换模型、加模型，客户端跟着变
- **不依赖 SSE 的 `usage` 尾包**。上游带 `stream_options.include_usage` 就顺带显示本次 token 数，
  不带就不显示——用量的事实来源始终是 `/api/v1/usage/summary`。这样上游换供应商、换版本都不会让客户端出错
- **模型缓存要能被证伪**：请求返回「模型不存在」（400/404 且消息里带模型名）时，清缓存重新拉一次
  `/v1/models` 再试一次，仍失败才报错给用户。降级期间模型被下线是必然会发生的事

### 7.3 额度展示

`GET /api/v1/usage/summary` 在三种时机读：

| 时机 | 目的 |
| --- | --- |
| 启动时（已登录） | 状态栏显示余量 |
| `/usage` | 详细 |
| 收到 402 / 额度类错误 | 解释发生了什么 |

**额度查询失败不能影响对话**。查不到就不显示，不要报错弹窗。

### 7.4 设备管理

登录时生成稳定的 `device_id`：首次生成 UUID，存本地配置。之后每次请求带上，平台侧 `/me/connected-apps` 才能列出「哪台机器」。

登出只吊销本设备，不影响同账号在其他机器上的登录。

### 7.5 匿名模式

没有平台账号时，用户自己配：

```toml
[providers.mine]
type   = "openai-compatible"
base_url = "https://api.example.com/v1"
api_key_env = "MY_API_KEY"      # 从环境变量读，不写进文件
models = ["some-model"]
```

`api_key_env` 优先于 `api_key`，配置文件里出现明文 key 时给一次警告。

### 7.6 错误与降级

**判定顺序：先看错误信封的 `code`，再看 HTTP 状态码。** 网关会透传上游的错误，同一个状态码可能有两种含义，
只认状态码一定会判错。信封格式见 `docs/api/conventions.md`。

| 情况 | 判定 | 行为 | 重试 |
| --- | --- | --- | --- |
| 令牌过期 | 401，或 `code` 含 `invalid_token` | 静默刷新一次；失败再提示 `/login` | 刷新后重试 1 次 |
| **配额耗尽** | 402；或 `code` ∈ `quota_exceeded` / `insufficient_quota` / `budget_exhausted`（**即使状态码是 429**） | 说清楚是队伍额度还是个人额度，建议切到自带 key | **不重试**，重试无意义 |
| **速率限制** | 429 且 `code` 不属于上面那组 | 读 `Retry-After` 倒计时，指数退避 | 最多 3 次，上限 60 s |
| 鉴权失败 | 403 | 不动令牌，说明权限不足（可能是队伍未激活、赛道未开放） | 不重试 |
| 请求非法 | 400 / 422 | 原样显示 `code` 与 `message`，不猜 | 不重试 |
| 服务端错误 | 5xx | 指数退避 | 2 次 |
| 超时 | 连接或流空闲超 120 s | 中断本次请求，保留上下文 | 2 次 |
| 网络完全不通 | 连不上 | 提示检查代理，不退出；`/doctor` 给出诊断 | — |

三条实现约束：

1. **402 与 429 的语义分工必须固定**：配额耗尽用 402（不可重试），速率限制用 429（可重试）。
   即便如此客户端也要同时认 `code`，因为上游网关会原样透传它自己的 402/429。
2. **流已经开始输出后出错**（SSE 中途断开、中途出现 error 事件）：已渲染的内容**保留**，
   末尾标注「连接中断，本次回复不完整」，不静默截断让人以为说完了。
3. **重试要对用户可见**。倒计时和「第 2/3 次重试」写在状态行里，不能让人干等。

## 8 工具集

模型能调用的全部能力。每个工具定义：输入 schema、权限档位、超时、输出上限。

| 工具 | 作用 | 权限 | 超时 | 输出上限 |
| --- | --- | --- | --- | --- |
| `read` | 读文件（支持行范围） | 只读 | — | 2000 行 / 单次 |
| `write` | 新建或整体覆写 | 写入 | — | — |
| `edit` | 精确字符串替换 | 写入 | — | — |
| `multi_edit` | 一个文件多处替换，原子生效 | 写入 | — | — |
| `glob` | 按模式找文件 | 只读 | 10 s | 500 条 |
| `grep` | 内容搜索（封装 ripgrep） | 只读 | 30 s | 200 条 |
| `bash` | 执行命令 | 写入 | 120 s（可配） | 30 KB |
| `todo` | 会话内任务清单 | 只读 | — | — |
| `fetch` | 取一个 URL 的正文 | 只读 | 30 s | 100 KB |

设计约束：

1. **工具数量克制**。九个够用；加工具前先问「能不能用 `bash` 做到」。
2. **`bash` 是唯一能改变系统状态的口子**，所以它的权限判定要最严：命令先过黑名单（`rm -rf /`、`mkfs`、`dd of=/dev/`、`curl | sh`），命中直接拒绝。
3. **输出超限要截断并说明**，不能让模型以为看全了。
4. **不提供 `apply_patch` 之外的批量改文件捷径**，防止一次改 500 个文件。

## 9 编辑正确性（最容易出事的地方）

旧版和所有同类工具踩过的坑都在这里，写进设计比写完再修便宜。

### 9.1 精确字符串替换

`edit` 的输入是 `old_string` / `new_string`，不是行号。

- `old_string` 在文件里**必须唯一**，不唯一则报错并要求模型给更多上下文
- 匹配前统一换行符（CRLF → LF）比较，写回时按原文件风格
- 不做模糊匹配、不做「猜你想改哪里」——宁可失败让人重试

### 9.2 原子写

写临时文件 → `fsync` → 重命名覆盖。中途断电不会留下半个文件。

### 9.3 diff 展示

改之前把 diff 摊开：上下文 3 行，新增/删除对齐，长 diff 默认折叠只显示统计。

### 9.4 并发与外部修改

文件在「读」和「写」之间被别的程序改了：

- 记录读取时的 `mtime` + 大小 + 内容哈希
- 写入前重新校验，不一致则**拒绝写入**并提示「文件已被外部修改」
- 不提供「强制覆盖」的默认路径，要用户明确确认

### 9.5 编码与换行

- 默认 UTF-8；检出 BOM 时保留 BOM
- CRLF / LF 按原文件
- 二进制文件（含 `\0`）拒绝 `edit`，只允许 `read` 提示「这是二进制」

## 15 边界与一致性约束

这一节收的是**不写清楚就会在实现时出错的判断**。每条都对应一个真实的失败场景。

### 15.1 权限判定的短路链

判定必须按顺序短路，不能并列投票：

```
1. 硬黑名单    rm -rf / 、mkfs 、dd of=/dev/ 、curl ... | sh 、shutdown
              → 直接拒绝，不问，不可通过配置开启
2. 路径越界    写项目根之外、系统目录、$HOME 根
              → 必问，且不提供「本会话都允许」
3. 项目内写入  改文件、跑命令
              → 默认问，可「本会话都允许」（只在内存里，不写盘、不跨会话）
4. 只读        读、搜、列
              → 允许
```

**为防**：「本会话都允许」被误当成全局放行，导致第 1、2 档失守。

### 15.2 没有浏览器时怎么登录

`intern login` 在无 GUI 环境（SSH、CI、无桌面会话的 macOS）不能直接失败：

1. 起 loopback 监听，同时打印完整授权 URL，并提示「如果这台机器没有浏览器，用别的机器打开」
2. 用户在别的机器上授权，浏览器会跳到那台机器的 `http://127.0.0.1:<port>/oauth/callback?...`，打不开
3. 所以同时进入**粘贴模式**：让用户把浏览器地址栏里那一整条 URL 粘回终端
4. 客户端从粘贴的 URL 里解析 `code` 与 `state`，校验 `state` 后继续走 `/oauth/token`

**为防**：服务器上敲 `intern login` 卡死在一个永远等不到的回调上。

### 15.3 一次性模式（`-p`）的工具权限

> 形态改为桌面应用后 CLI 暂不存在，此条**待 CLI 回归时生效**，先保留结论。

交互模式靠「问」兜底，一次性模式没人可问，所以规则不同：

| 工具档位 | `-p` 下的默认行为 |
| --- | --- |
| 只读 | 自动允许 |
| 项目内写入 | **默认拒绝**，除非 `--allowed-tools write,edit,bash` 或 `--yes` |
| 硬黑名单 / 路径越界 | 拒绝，且 `--yes` 也打不开黑名单 |

被拒时**必须把拒绝原因作为工具结果回给模型**，让模型能换策略（比如只给 diff 不落盘），
而不是当成「工具返回空」。

**为防**：模型拿不到明确反馈，反复重试同一个被拒的操作把上下文撑爆——同一工具连续被拒 3 次即终止并报错。

### 15.4 中断之后的文件状态

`Esc` / `Ctrl-C` 的语义分两种：

| 中断时处于 | 行为 |
| --- | --- |
| 请求中（还没收到工具结果） | 取消请求，不发任何工具 |
| 工具执行中 | 向子进程发中断信号，等 3 秒，未退出则强杀 |

中断后必须做一件事：**清空所有文件的基线记录**（mtime / 大小 / 哈希）。已落盘的写入不回滚，
但下次 `edit` 前要重新读——否则会用中断前的旧基线做外部修改检测，误判成「文件被外部修改」。

**为防**：中断后第一次编辑永远失败，且用户不知道为什么。

### 15.5 多进程同时刷新令牌

两个 `intern` 窗口同时运行、令牌同时过期 → 都去刷新 → 令牌轮换后第一个成功、第二个拿着已失效的
refresh_token 请求，被平台判定为令牌重放，**可能把整个设备的授权踢掉**。

规则：

1. 刷新前对 `~/.intern/lock` 加排他锁（Unix `flock`，Windows 独占创建）
2. **拿到锁后先重读钥匙串**：如果磁盘上的令牌比内存里的新，说明别人已经刷过，直接用新的，不发请求
3. 同进程内的并发请求共享同一次刷新（单飞）

### 15.6 上下文超限

MVP 不做自动摘要，但**必须有裁剪**，否则长会话会收到 400 且无法自救：

- 估算超阈值 80% 时，**从最旧的工具输出开始裁**（保留对话轮次，工具结果最不重要）
- 裁完全部工具输出仍超限：提示 `/clear`，并给出「已用 N 轮、建议保留什么」的建议
- 裁剪发生时在状态行留一个可见标记，不静默进行

### 15.7 工具并发

模型一次可能返回多个 tool_call：

- **只读工具并行**，上限 4（避免把用户机器打满）
- **写入工具串行**，按模型给出的顺序执行
- 两个写操作命中同一文件 → 串行，且每次执行前重读文件

**为防**：两个 `edit` 并行改同一个文件，第二个基于过期内容写入，静默丢改动。

### 15.8 代理

Go 的 `http.ProxyFromEnvironment` **只读 `HTTPS_PROXY` / `HTTP_PROXY` / `NO_PROXY`，不读操作系统代理设置**。
macOS 的系统代理、Windows 的「Internet 选项」里的代理，Go 都看不见。

- 尊重上面三个环境变量（默认行为）
- `/doctor` 必须报告「当前是否走代理、走的哪个」——否则用户配了系统代理却以为生效了
- 支持 `--cacert` 指定自签证书（企业代理会做 TLS 中间人）
- 不提供「跳过证书校验」的开关

**为防**：国内网络环境下最常见的困惑——「我明明挂了代理，为什么连不上」。

### 15.9 显示宽度

> 改为 Web 前端后，排版由浏览器负责，此条**不再适用**；保留是因为它解释了当初
> 为什么不用纯 Go 原生 GUI。

TUI 排版必须按**显示宽度**算，不是字符数也不是字节数：

- 中日韩字符、全角符号占 2 列
- emoji、组合字符（ZWJ 序列）宽度容易算错
- 折行、对齐、进度条全部按显示宽度计算

用成熟库，不要自己数 `len()`。**为防**：中文界面下框线错位、折行把字劈开——这类 bug 在 TUI 里极其常见且难查。

### 15.10 升级时替换正在运行的自己（首版不做自升级，保留结论）

| 平台 | 做法 |
| --- | --- |
| macOS / Linux | 可以直接把新文件 rename 覆盖旧文件 |
| Windows | **运行中的 exe 不能被覆盖或删除**。下载到同目录 `intern.new`，提示「重启以完成升级」；下次启动时检测到 `intern.new`，先把自身改名 `intern.prev`，再把 `intern.new` 改成正式名 |

**为防**：在 Windows 上执行 `intern upgrade` 报「文件被占用」，用户以为升级坏了。

### 15.11 会话归属哪个项目

项目根 = `git rev-parse --show-toplevel` 的输出；不是 git 仓库就用当前目录。

会话按项目根路径的哈希分目录存放，**不是按 cwd**。

**为防**：在 `src/pages` 里敲 `intern` 又开出一个全新的空会话，历史全丢——这是子目录启动最常见的困惑。

### 15.12 切换模型 / 通道时

- **保留上下文**：切模型不清空对话
- **立刻按 15.6 重新裁剪**：新模型窗口更小的话，不能等到发请求被 400 才处理
- **必须探测工具调用能力**：切到自带 key 的通道时，先确认该 provider 支持 `tool_calls`。
  不支持就降级成纯对话模式并**明确告知用户**——否则模型会写一堆「我已经改好了」但其实什么也没做，
  这是弱绑定方案里最危险的失败方式

### 15.13 只读工具也不能满盘读

`read` / `glob` / `grep` 默认范围是项目根：

- 越界读取（`~/.ssh`、`/etc`、其他项目）必须问，且不提供「永久允许」
- `grep` / `glob` 不给路径参数时，起点是项目根，**永远不是 `/` 或 `~`**
- 这些工具的权限档位是「只读」，但**范围限制是独立的**，不受「只读默认允许」影响

**为防**：一句「帮我看看这台机器的配置」，模型就把私钥和凭据读进上下文、再发给模型服务商。
